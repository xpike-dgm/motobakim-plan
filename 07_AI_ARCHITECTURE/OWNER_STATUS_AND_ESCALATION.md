## Status-line format

One line per task: Task ID + state + plain outcome/next step. No technical content, ever (DEC-0029/0051).

## BLOCKED option cards

Each card: options + cost/delay + recommendation, in plain outcome/risk/cost/reversibility language.
Step-mapped to the change protocol: Step 4 options incl. keep-old → Step 5 re-scope→REVIEW only on explicit
approval with SUPERSEDED preservation → Step 6 different-chat checklist → Step 7 push only on explicit
authorization. (Cross-reference to `CHANGE_CONTROL.md`, Group 5 — not redefined here.)

## Reviewer selection (Path C compatible)

Reviewer is a different chat than the implementer. Quota rotation across the owner's tools is allowed.
Chats are opened manually by the owner; reviewer outputs stay isolated until manager synthesis. Paid API
actuation is not assumed.

## End-to-end BLOCKED path

BLOCKED → owner decision (options card) → change-request → narrow remediation → different-chat re-review →
REVIEW. The owner never carries technical content and never debugs (DEC-0029/0051).
