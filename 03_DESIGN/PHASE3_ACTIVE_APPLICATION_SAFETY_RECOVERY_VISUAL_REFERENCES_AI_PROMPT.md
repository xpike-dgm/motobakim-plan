## CORE FAMILY RULES

### One dominant physical objective
Normal active step:
1. Ne yapacagim?
2. Nereye bakacagim?
3. Bitirince neye basacagim?

Safety/trust/recovery accessible kalir but consequence gerektirmedikce primary task ile rekabet etmez.

### Recovery is not continue-anyway
Unexpected/mismatch state:
- normal progression stops,
- safe current state becomes primary,
- reason + observation/evidence + re-entry path is shown,
- no `yine de devam et`.

### Saved UI != current physical proof
Resume after interruption:
- prior progress can be remembered,
- current physical/safety state must be revalidated where consequence requires,
- user saying `degismedi` cannot bypass critical checks.

### Guide change != automatic reversal
Material guide update/change:
- old continuation stops,
- what changed / why it matters is explained,
- current physical state is captured/reviewed,
- safe mapping is required before continuation,
- never auto-reverse old physical steps,
- never guess nearest new step.

### Completion != forced success
Closure must support truthful outcomes:
- completed when required confirmation exists,
- partial/incomplete,
- unresolved/problem remains,
- safely stopped/closed where applicable.

Partial/unresolved cannot be silently coerced to completed.
Safe closure cannot be paywalled.

## GENERATE NEW VISUALS — E02 TO E05

E01 is existing V10 reference. Generate exactly **4 new separate mobile visuals**:

### E02 — SCR-015 / Problem / Mismatch / Recovery

Trigger fixture:
User taps `Sorun var` or notices unexpected/mismatched physical state during the active step.

Purpose:
Stop normal progression and establish safe recovery.

Required hierarchy:
1. clear `Dur / Sorun var` state without panic theatrics,
2. concise statement that normal progression is paused,
3. one current-observation/evidence capture path,
4. concise safe-state guidance,
5. one dominant `Durumu yeniden kontrol et` / revalidation action,
6. lower-emphasis exit/safe-closure path where appropriate.

Do NOT:
- offer `devam et`,
- diagnose unsupported cause,
- recommend random part replacement,
- show huge stack of warning cards.

### E03 — SCR-016 / Resume Revalidation

Fixture:
User returns after interruption to an already-started physical job.

Purpose:
Re-establish current physical reality before returning to active application.

Required:
- clear `Devam etmeden once yeniden kontrol` meaning,
- prior guide/step context can be shown compactly,
- a small number of critical revalidation checks,
- current-state evidence/confirmation where appropriate,
- one dominant `Yeniden dogrula` action,
- progression stays closed until required checks pass.

Do NOT:
- reopen last visible step automatically,
- treat saved progress as current proof,
- let `hicbir sey degismedi` bypass critical checks.

### E04 — SCR-017 / Material Guide Change / Physical-State Remap

Fixture:
Guide materially changed while user has an interrupted/partially executed physical state.

Purpose:
Explain the change and safely map the current motorcycle state before any further instruction.

Required hierarchy:
1. `Rehber guncellendi / bu durum mevcut isi etkiliyor` meaning,
2. concise what-changed + why-it-matters summary WITHOUT invented technical values,
3. current physical-state review/capture,
4. explicit statement that previous next-step continuity is paused,
5. one dominant `Mevcut durumu eslestir` / revalidation action,
6. recovery/safe closure if mapping cannot be established.

Do NOT:
- automatically reverse previous work,
- guess new step number,
- imply old confirmation is still valid.

### E05 — SCR-018 / Completion / Safe Closure / Record

Purpose:
Close the physical-work session truthfully without forcing success.

Required:
- concise outcome question,
- clear distinction between actual outcome states,
- support at least:
  - completed,
  - partial/incomplete or unresolved,
  - safely stopped/needs follow-up,
- completion wording must not imply professional certification or guaranteed workmanship,
- record/history consequence is understandable,
- one selected outcome leads to record/save confirmation.

Keep the screen calm and scannable. Do not show all provenance/history detail at once.
