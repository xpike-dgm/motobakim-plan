## APPROVED PRODUCT RULES — MUST PRESERVE

### SCR-009
User yapmak istedigi isi plain language ile bulabilir.
Task secimi tek basina motorcycle fit/readiness authority DEGILDIR.

### SCR-010
User su sorulari anlamalidir:
- Bu rehber neyi kapsiyor?
- Benim motosikletim/variant'im icin yeterince eslesiyor mu?
- Uygulamaya gecilebilir mi?
- Trust/freshness/uncertainty nedir?

`Verified` veya `dogrulanmis` = guaranteed success DEGILDIR.
Unresolved fit variant-specific application'i acamaz.

### SCR-011
Physical intervention oncesi gerekli preparation/readiness gorunur:
- gerekli arac/malzeme kategorileri,
- work-area / motorcycle stability gibi relevant prerequisites,
- critical safety checks,
- mandatory vs optional ayrimi.

Eksik mandatory condition varsa physical step acilmaz.

### SCR-012
Block/hold dead-end DEGILDIR.
Mutlaka:
- ne eksik,
- neden gerekli,
- nasil giderilebilir,
- nasil tekrar kontrol edilir
anlasilmalidir.

`Hazirim` / user self-assertion critical gate'i bypass edemez.

### SCR-013
Learning/reference application kapali olsa bile acik kalabilir.
Teaching-only ekran physical instruction gibi gorunmemeli ve user'i uygulamaya hazir/authorized hissettirmemelidir.

## GENERATE EXACTLY 5 SEPARATE MOBILE VISUALS

### D01 — SCR-009 / Known Task Find / Select
Purpose:
User ne yapmak istedigini kendi diliyle belirtir ve uygun task candidate'ini secer.

Required:
- compact selected motorcycle context,
- clear task input/search affordance,
- illustrative user wording,
- one clear candidate/result path,
- no dashboard of popular tasks,
- no technical answer generated in this screen.

### D02 — SCR-010 / Guide Scope + Fit Preview
Purpose:
User rehberin kapsam, motorcycle fit, trust/freshness ve application eligibility meaning'ini anlar.

Required hierarchy:
1. topic/guide title,
2. compact motorcycle context,
3. fit/applicability state,
4. concise trust/freshness state,
5. scope summary,
6. one dominant next action when application may proceed,
7. lower-emphasis deeper provenance/detail.

Do NOT:
- use giant shield/check certification badge,
- imply guarantee,
- hide unresolved fit.

### D03 — SCR-011 / Preparation & Readiness
Purpose:
User physical intervention'dan once neyin hazir olmasi gerektigini gorur.

Required:
- concise preparation title/context,
- small number of scannable prerequisite groups,
- mandatory vs optional clear,
- critical safety prerequisite visible,
- one dominant continue/start action ONLY for application-ready fixture,
- progressive detail rather than card-per-item explosion.

U04'u literal kopyalama; bu active physical step DEGILDIR.

### D04 — SCR-012 / Readiness Hold + Recheck
Purpose:
Bir critical prerequisite dogrulanamadigi icin application durur.

Illustrative generic hold:
`Motosikletin guvenli/sabit calisma konumu dogrulanmadi.`

Required:
- clear stop reason,
- why it matters,
- remediation guidance,
- evidence/recheck action,
- optional teaching/reference path,
- no `yine de devam et`,
- no dead-end warning-only screen.

### D05 — SCR-013 / Teaching-Only
Purpose:
Application simdilik kapaliyken learning/reference degeri korunur.

Required:
- clearly label learning/reference mode,
- explain why application is unavailable,
- useful conceptual content can remain accessible,
- route to resolve/recheck where appropriate,
- must NOT resemble numbered physical application instructions,
- must NOT show completion CTA that implies the work was performed.
