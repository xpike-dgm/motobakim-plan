## Required Constraints

### 1. D03 readiness-state constraint — REQUIRED

The screenshot shows `Uygulamaya hazir`. Canonical meaning:
- this status may appear **only after all mandatory and critical readiness conditions have actually been verified for the current context**,
- if any mandatory/critical condition is pending, unknown, stale or failed, the screen must not claim application-ready state,
- `Rehberi baslat` cannot become an active application CTA merely because the user says they are ready,
- unresolved critical state must route to hold/recheck semantics such as D04.

Therefore D03 is interpreted as an **illustrative ready-state fixture**, not as permission to show ready while critical checks remain pending.

### 2. L05A brand-fidelity drift — REQUIRED

D01–D05 generated screenshots redraw the approved logo into a blue K-like mark that is not the canonical L05A working direction.

This generated mark is **NOT APPROVED** and creates no new logo authority.

Downstream visual work must:
- preserve L05A as the working logo direction,
- not infer a blue K redesign from D01–D05,
- prefer the attached approved L05A visual as-is or reduce brand-mark prominence rather than inventing a new mark when exact reproduction is unreliable.

### 3. Generic preparation examples are not technical truth — REQUIRED

D03 contains illustrative preparation wording such as `Ek aydinlatma veya eldiven`.

This visual does **not** approve that item as optional/required for any real motorcycle/task. Production content must come from validated task-specific guidance. The same rule applies to any generated tools/materials/safety examples.

### 4. D02 fit/trust copy is fixture-dependent — REQUIRED

`Motosikletim icin uygunluk dogrulandi` and freshness/review language may only be shown when the real underlying evidence supports that state. The screenshot is a visual fixture, not evidence that any real motorcycle/guide combination is compatible.

### 5. Bottom-bar treatment remains PROPOSED

D01/D02 show the bottom bar; D03–D05 reduce/remove it. This visual family does not finalize routing or navigation visibility. Active physical-work navigation remains an open design decision.
