## Visual Family Authority

The set authorizes a coherent Phase-3 root-level visual direction with:
- near-white canvas,
- dark graphite/navy typography,
- restrained electric-blue accent,
- low decoration,
- moderate rounding,
- strong title hierarchy,
- restrained Kavriva/L05A presence,
- one primary job per root,
- persistent five-tab shell after first-use context is established.

## Root Responsibilities

### R01 — Garaj
Primary job:
selected motorcycle context / switching / lifecycle entry.

Working visual pattern:
- motorcycle context can be visually prominent,
- switching and motorcycle-info actions remain focused,
- no feature-dashboard/KPI expansion.

Generated motorcycle imagery is illustrative only and is not identity/fit evidence.

### R02 — Bakim
Primary job:
understand due/upcoming/uncertain maintenance.

Working visual pattern:
- scannable maintenance list,
- status is concise,
- no generic score/chart dashboard.

Deeper rule:
a maintenance row/detail must provide an explicit path to perform/open the relevant guide flow when applicable; Bakim is not a dead reminder list.

### R03 — AI Usta
Primary job:
choose known-task vs symptom-first assistance.

A1 remains authority:

- `Nasil yardimci olayim?`,
- `Bir is yapmak istiyorum`,

- low-prominence help.

The screenshot's motorcycle crop is optional visual treatment, not a new required A1 hierarchy element.

### R04 — Gecmis
Primary job:
scan/search motorcycle history and open evidence/provenance detail.

Working visual pattern:
- searchable chronological/scannable list,
- no default KPI analytics,
- record type can be visible without implying verification authority.

### R05 — Topluluk
Primary job:
read/discover community experiences/Q&A that remain separate from official guide authority.

Working visual pattern:
- searchable topic/content entries,
- contribution is available,
- no infinite-social-feed convention.

`Katki yap` exact prominence is not locked; contribution must not displace reading/discovery as the root's primary product job.
